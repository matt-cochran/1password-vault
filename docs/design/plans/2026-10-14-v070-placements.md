## Foundation design (config-model)

Model:
- `Environment { name, boundaries: BTreeMap<String, Boundary>, targets: BTreeMap<String, Target>, modes, confirm_env, account, title, audience, order, personal_vault, personal_item }`
- `Boundary { vault_id, item_id }`
- `Target { name, config: Box<dyn TargetConfig>, products: Option<Vec<String>>, deploy_credentials: Option<ItemRef>, state_vault_id: String }`
- `Product { source_only, boundary: Option<String>, keys }`
- `Fleet { environments, products, origin }`: there is no profile.
- `Fleet::boundary_of(product)` is the product's `boundary`, or else its name.
- `Fleet::boundary(env, product)` returns the recorded `Boundary`.
- `Fleet::delivers(env, target, product)` replaces `TargetConfig::serves`.

Load:
- Targets are only `[environments.<env>.targets.<name>]`. A target holds one provider
  section plus `products`, `deploy_credentials` and `state_vault_id` (required, D12).
- Boundaries are `boundaries.<name> = { vault_id, item_id }`.
- Every product with a key desired in an environment needs its boundary recorded there
  (`boundary_missing`).
- The `(provider, locator)` uniqueness check runs between the targets of an environment and
  across environments.
- `wider_than_values` runs at load (`domain::placement`).

Removed forms fail at load and show the current form:
- `[profile]` and top-level `[keys]`;
- an environment-level `vault_id`/`item_id`, provider table, `deploy_credentials` or
  `state_vault_id`;
- GitHub's `products`;
- a bare `from = "KEY"`.

The `profile` parameter of provider parsing, `Profile`, `SIMPLE_PRODUCT` and
`SIMPLE_TEMPLATE` are removed.

Decisions made during execution:
- **D11:** the ledger folds into the per-placement evidence.
- **D12:** a state vault is required per target.
- **`target add` creates the state vault.** It creates and records the target's state vault in the same step.
- **Personal-only products need no boundary.**
- **The width error names targets as `env/target`.**
- **Fixture conversion rule:** products that shared one environment item become the opt-in group `boundary = "core"`, and the single target is named `app`.

Lessons:
- Junior's default 10-minute deadline is too short when several cold cargo builds run at once. Contracts set `execution.deadlineMs` to 30–45 minutes, and at most 4 cargo-heavy handoffs run at a time.
