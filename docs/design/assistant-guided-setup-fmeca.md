# FMECA: assistant-guided configuration (calibrated)

Subject: [assistant-guided-setup.md](assistant-guided-setup.md), Parts I–V as written, with Part VI's reframings (R1–R7, §22) mapped against every failure mode. Inputs: six DeepSeek worker analyses (runtime, ergonomics, confidentiality, consistency, recovery, adoption; 78 raw failure modes), the independent [review](assistant-guided-setup-review.md) (H1–H4, M1–M14), and the code at v0.11.0. Reviewer: FMECA reviewer agent, 2026-10-18. The design doc was not edited and nothing is committed.

Formal record: seven fmeca-mcp `technical_plan` sessions in `.delivery/fmeca/fmeca-state/` (the hop's state directory), parent `assistant-guided-setup-technical-plan` with six children `asg-<perspective>-technical-plan`. Exports are in `.delivery/fmeca/export/`. `fmeca-mcp check` passes on all seven logs.

## How the scores were calibrated

The workers rated 72 of 78 failure modes high (runtime 12 of 12). Most of these were design-only failures in features that aren't built yet, where the effect is an error the person can recover from, but the workers scored them as `service_outage` or `security_breach` with `happens_in_normal_use`. These rules were applied to every failure mode, the workers' and the review's alike:

- **`security_breach`** only when a usable value can reach an assistant-readable surface or another unintended reader, or when access control is lost. A disclosed class or bit, whose remedy is rotation, counts as `recoverable_error`.
- **`service_outage`** only when the running application fails: rotation or revocation, retirement pruning, or a key missing in production. A blocked release or a failed CI job counts as `recoverable_error`.
- **`happens_in_normal_use`** only when the ordinary journey, as written, triggers the failure, for example §6.1's import-before-structure order. `known_recurring` only where this project has already seen it: the 0.10.0 redaction corruption.
- **`requires_misuse`** for oracle attacks that need an assistant, or a prompt-injected one, to act deliberately. With high severity this still scores **medium**: it stays open until it is mitigated.
- **Residuals.** Prevention lowers probability. Severity drops only when a detection or gate turns the failure into a refusal before harm. Where a value-exposure or outage path survives, the residual stays **medium**, because the 3×3 matrix never scores high severity as low. The doc says this plainly rather than tuning observations to reach low.

The matrix: 3+3 and 3+2 score high, 3+1 and 2+2 medium, and anything lower scores low. This was checked against the tool.
